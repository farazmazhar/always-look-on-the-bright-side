Great question! Here's a breakdown of the key differences:


Bubble Sort is a simple comparison-based algorithm:

Time complexity: O(n²) average and worst case
Space complexity: O(1) — in-place
Stable: yes — preserves order of equal elements
Best for: educational purposes, nearly-sorted small datasets

Quicksort uses a divide-and-conquer strategy:

Time complexity: O(n log n) average, O(n²) worst case
Space complexity: O(log n) due to recursion stack
Stable: no — standard implementation is not stable
Best for: general-purpose sorting, large datasets

Here's a clean Python implementation of quicksort:

python 
def quicksort(arr):
    if len(arr) <= 1:
        return arr

    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]

    return quicksort(left) + middle + quicksort(right)


# Example usage
data = [38, 27, 43, 3, 9, 82, 10]
sorted_data = quicksort(data)
print(sorted_data)  # [3, 9, 10, 27, 38, 43, 82]

Here's the in-place quicksort using Lomuto partition:

python 
def lomuto_partition(arr, low, high):
    pivot = arr[high]
    i = low - 1

    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]

    arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1


def quicksort_inplace(arr, low=0, high=None):
    if high is None:
        high = len(arr) - 1

    if low < high:
        pi = lomuto_partition(arr, low, high)
        quicksort_inplace(arr, low, pi - 1)
        quicksort_inplace(arr, pi + 1, high)


# Example
data = [38, 27, 43, 3, 9, 82, 10]
quicksort_inplace(data)
print(data)  # [3, 9, 10, 27, 38, 43, 82]

Key differences from the functional version:

Sorts in-place — no extra memory for new lists
Space complexity drops to O(log n) for the recursion stack only
More cache-friendly since it operates on contiguous memory
